# Employee Directory

A cross-platform Employee Directory mobile app built with Flutter for the Flutter Developer technical assessment. It follows the supplied UI design reference and integrates the provided REST API (Postman collection).

> Tested on Android (physical device and emulator). iOS code is generated by Flutter but has not been run.

## Features

- Splash screen with automatic session restore
- Registration (profile photo, department dropdown loaded from the API, date picker) and login
- Forgot password flow: send OTP, verify OTP, reset password
- Employee directory: list, inline search (debounced), department filter chips, pull-to-refresh, pagination
- Employee details with call, SMS and email actions
- Departments list, with a filtered employee list per department
- My Profile, Settings and logout with confirmation (clears the stored token)
- Loading, empty, validation, network-error and expired-session (401) states throughout

### API configuration

All URLs live in one file: `lib/core/config/api_constants.dart`.

- `baseUrl`: `https://ed.alobhadev.com/api`
- `imageBaseUrl`: prefix used to turn the relative `profile_image_url` values into full URLs

No tokens or credentials are hardcoded. The JWT is stored with `flutter_secure_storage` after login.

### Trying the app

There is no shared test account in the repository. Create one with the in-app **Register** screen (a profile photo is required), then log in with it.

## Architecture

```
Screen (UI)  ->  Provider (state)  ->  Repository (data)  ->  Dio client (network)
```

- **Screens / widgets** only render state and call provider methods. They never touch Dio.
- **Providers** (`ChangeNotifier`) hold state as a `ViewStatus` enum (`initial / loading / success / empty / error`) plus data and an error message.
- **Repositories** are the only classes that know the endpoints. They return models and convert every `DioException` into an `ApiException` with a user-friendly message.
- **Dio client** has one interceptor that attaches the Bearer token and, on a 401 for a logged-in request, clears the token and triggers logout. The router then redirects to login.
- **Routing** uses `go_router` with a redirect driven by `AuthProvider`, so login, logout and session expiry all use the same code path.

### Folder structure

```
lib/
  main.dart
  app.dart                  # dependency wiring (MultiProvider) + MaterialApp.router
  core/
    config/                 # api_constants.dart
    network/                # dio_client, auth_interceptor, api_exception
    storage/                # token_storage (secure storage wrapper)
    theme/                  # app_colors, app_theme
    utils/                  # validators, view_status, json_utils, url_launcher_helper
  models/                   # Employee, Department
  repositories/             # auth, employee, department
  providers/                # auth, employee_list, department, password_reset
  routes/                   # app_routes (go_router config + redirect rules)
  screens/                  # splash, auth, home, employees, departments, profile, settings
  widgets/                  # shared UI (buttons, fields, tiles, loading/empty/error views)
```

### Notable implementation details

- **Stale-response protection:** the employee list provider tags each request and ignores responses from outdated ones, so fast typing in search cannot show results for an older query.
- **Defensive parsing:** the API returns some values with inconsistent types (for example `department_id` as `"2"` or `2`), so models parse through small helpers and never crash on null.
- **Session restore:** on launch the splash screen validates the stored token via the profile endpoint. An expired token is cleared; a network failure keeps the token so the user is not logged out for being offline.
